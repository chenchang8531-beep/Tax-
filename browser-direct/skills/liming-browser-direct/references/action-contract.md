# Browser Direct v0.5.0 action contract

- `browser_task_open`: canonical `xeroOrgRef+returnRef` lock; provisional `PENDING_RETURN` key is tenant+legal entity+FY/period+form. Concurrent lease collision is atomic at OS filesystem. Reserve/commit action WAL is atomic across processes and never replays uncertain effects after reboot.
- `browser_task_create_return` with verified obligation and no-duplicate evidence; `browser_task_promote_return` requires real Xero Return ID in route. Both stop if exact evidence unavailable.
- `browser_task_bind` requires separate initial anchors and scoped `formGuard` for production Chrome. A stable-looking header outside the active form is not identity. Fast batch continues without full identity polling. Pause/restart/changed document/guard exception forces full revalidation.
- `browser_task_plan`: freeze >=2 unique mandatory return sections and source workpaper version. `browser_task_checkpoint` requires one distinct same-session persisted Save/reload receipt per section. Other sections cannot reuse a receipt.
- `browser_task_finish`: after all sections checkpointed, one final comprehensive identity audit and at most 12 current field checks; result `UI_AUDIT_COMPLETE_AWAITING_DOMAIN_REVIEW`, never whole-tax pass or automatic Tab close. `browser_task_review_approve`: externally Ed25519 signed receipt bound to task digest + plan + coverage digest; no public key => fail closed. `browser_task_close` allowed only after accepted review or a never-modified unbound tab.
- Connection: `mcp.json` is a declaration only until host connector is configured; production Windows needs verified exclusive CCOS-compatible writer and current `conversation_state_ref/revision/latest_event_ref/consumed_state_keys` verifier. No manually self-declared PASS.
- Strict local Chrome CDP 9222, server 59422, genuine Gateway TLS with separate secrets, outbound Windows Agent. All user amounts and secrets excluded from journals. No irreversible actions.
